# ADR-010: Dependabot cooldown セキュリティポリシー

| 項目 | 値 |
|------|-----|
| 決定日 | 2026-03-29 |
| ステータス | 承認済み（有効） |
| 発生契機 | Copilotレビュー指摘によりcooldownが削除されたインシデント |
| 関連PR | [PR #27](https://github.com/suchi/sucheme-go/pull/27) |

## コンテキスト

Dependabot v2 の `cooldown` 設定は、新しい依存関係バージョンが公開されてから一定期間PRの作成を遅らせる機能である。この遅延により、悪意あるリリース（typosquatting、アカウント乗っ取り、サプライチェーン攻撃等）がコミュニティによって検出・報告される時間が確保される。

### インシデントの経緯

1. `.github/dependabot.yml` に `cooldown` 設定を追加
2. Copilotレビューが `cooldown` を「無効なキー」と指摘（当時のキー名が `default-days` ではなく別の形式だった）
3. **レビュー指摘に従い cooldown 設定を削除するミスが発生**
4. ユーザーの指摘により問題を認識
5. cooldown を復元し、正しいキー名（`default-days`, `semver-major-days`）に修正

## 決定

以下のポリシーを策定し、`CLAUDE.md` に明記する:

1. **cooldown設定の削除は禁止** — レビューツールが「無効なキー」と指摘しても、ただちに削除してはならない
2. **「無効なキー」指摘への対応**: Dependabot公式ドキュメントで仕様を確認し、キー名を**修正**する（削除ではなく修正）
3. **cooldownの完全な削除や事実上無効化する変更**: ユーザーの明示的な指示がない限り禁止
4. **サブエージェントやセッション変更を跨いでもルールは常に適用**

## 理由

1. **サプライチェーン攻撃の防御**: cooldown なしでは悪意あるバージョンが公開直後にPR化され、自動マージで取り込まれるリスクがある
2. **レビューツールの誤判定への耐性**: ツールが仕様を正しく把握していない場合でも、セキュリティ機能が削除されないようにする
3. **インシデントの再発防止**: 同種のミスが二度と発生しないように明文化

## 設定内容

```yaml
# .github/dependabot.yml
cooldown:
  default-days: 3        # 新バージョン公開から3日間待機
  semver-major-days: 7   # メジャーバージョンは7日間待機
```

## 教訓

**レビューツールの指摘はすべてが正しいわけではない。** 特にセキュリティに関わる設定の変更・削除は、公式ドキュメントで裏付けを取ってから判断すること。「ツールが言ったから」は削除の正当な理由にならない。
